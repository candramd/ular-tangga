## Hosting configuration

The Pages workflow in `.github/workflows/pages.yml` builds `out/` and deploys it with the official GitHub Pages actions. Set repository variable `NEXT_PUBLIC_SUPABASE_URL` to the project HTTPS URL and repository secret `NEXT_PUBLIC_SUPABASE_ANON_KEY` to its publishable/anon key. That key is public by design and is embedded in the static bundle; never put a database password, service-role key, admin secret, or other privileged credential in a `NEXT_PUBLIC_*` value. Enable GitHub Pages with GitHub Actions as the build and deployment source. The workflow sets `NEXT_PUBLIC_BASE_PATH` from the repository name for project-site URLs.

Build locally after setting those two public values and the repository base path:

```sh
NEXT_PUBLIC_BASE_PATH=/ular-tangga \
NEXT_PUBLIC_SUPABASE_URL=https://PROJECT.supabase.co \
NEXT_PUBLIC_SUPABASE_ANON_KEY=PUBLIC_PUBLISHABLE_KEY \
npm run build
node scripts/static-preview.mjs out
```

Open the local preview at `http://127.0.0.1:4173`. Room and game navigation use URL fragments (`/#/room/CODE` and `/#/game/ID`) so GitHub Pages does not need server rewrites. Admin remains a static `/admin/` page under the configured base path. The preview server binds to loopback only.

After building, run `node scripts/check-static-export.mjs out` to confirm both exported entry pages exist and scan generated text assets for server-only credential/config markers. The check reports whether a marker exists but never prints matched content. Run `node scripts/check-game-graphics.mjs` to compare the six board, dice, snake, and animation source files with the migration-start checksum baseline in `tests/fixtures/game-graphics.sha256`.

## Rollback

For a Pages-only rollback, select and verify a successful GitHub Pages workflow run for the desired known-good commit before rerunning it. At the 2026-10-14 release audit, verified examples are `7deb63e` / run `38532295267` (documentation follow-up) and `11b303d` / run `38532120396` (polling lifecycle release). Confirm the artifact and deployment status for the chosen run before acting. A workflow rerun keeps its original commit/ref while using current repository configuration and secrets. The previous and current artifacts both use the Supabase RPC backend. The local rehearsal script switches between downloaded artifact archives under a loopback preview only; it does not alter production. If the exclusive RPC gate must be restored as an emergency, run `psql --set ON_ERROR_STOP=1 --single-transaction --file scripts/recovery/restore-exclusive-rpc-gate.sql` only after stopping RPC traffic and confirming no RPC or Go writer holds its lock. This recovery SQL is deliberately outside the forward migration directory; it preserves and checks the state version/digest and permissions. Reapply migration 008 to restore shared RPC concurrency. A Go-writer recovery is not available through the current Pages artifacts; it would require an independently prepared compatible frontend/API route, auth and CORS configuration, traffic switch, and data reconciliation plan. Stop or route RPC traffic before enabling Go’s exclusive writer lock; never run both writers against the same state. Preserve the private snapshot and reconcile any newer writes before restoring an older state. Do not drop migrated tables or delete snapshot rows during rollback.
